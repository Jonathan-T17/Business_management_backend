## Issue found and fixed

New-draft attachment queries could cache an empty file list before uploads finished. Navigation to the saved entry then reused that cached empty result, even though the file was stored safely and appeared after reloading. The start-form success handler now awaits attachment-query invalidation before navigation. A second new draft verified the file appears immediately without reloading.

Post-fix TypeScript and targeted lint passed. The actual frontend save helper regression harness also passed required/hidden/inactive answers, nested errors, upload retry and lost create/submit response cases. This cache fix did not change backend validation or permissions.
